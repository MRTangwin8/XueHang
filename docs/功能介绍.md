# 学航 · 功能介绍

学航是面向各类培训机构的 CRM 与教学管理系统，覆盖招生、学员、排课、成绩、教学服务与人事协作。考试类型、成绩科目、档案字段和下拉选项都可以通过「行业模板」一键适配，内置日本升学私塾、中国中小学培训机构、语言培训机构和通用培训机构四套模板。本文依据当前数据模型、页面、接口和 `server/src/dict.ts` 的 `RULES` 编写；菜单名称采用中文界面名称，实际可见内容取决于账号权限。

## 1. 信息中心

**解决什么问题：** 将日常任务与学校信息集中呈现，减少在多个业务页面间查找。

**能做什么：** 首页展示最新通知、资料下载、今日自己的课程与面谈，以及按权限显示的待分配文书、待我批改文书、待打印资料和待审核工资等入口。可进入「我的日报」，有权限者可发布通知、查看「全员日报」。

**关键规则：** 今日课程按当前登录教师查询，不代表全校课程；待办按岗位生成。日报每人每天一条，可更新和补写 30 天内的日报，不能填写未来日期；全员日报支持按员工、日期和未读状态查看并记录已阅。薪资待办数量与薪资审核页可能采用不同范围，应以审核页返回的可审核明细为准。

## 2. 客户管理

**解决什么问题：** 记录潜在客户来源与沟通进展，协调销售归属并跟踪招生转化。

| 页面 | 能做什么 | 关键规则 |
|---|---|---|
| 我的客户 | 新建、查重、搜索、录入跟进、设置意向与下次跟进、放入公海 | 主要操作本人名下客户；支持今日待跟进筛选 |
| 公海客户 | 查看无负责人的客户并领取 | 领取时重新校验归属，同一客户不能被重复领取 |
| 全部客户 | 在授权范围查看、分配、删除、从回收站恢复客户 | 「全部客户」仍受校区范围约束；已转学员的客户不能删除 |
| 渠道管理 | 维护来源渠道、排序、启停，查看关联数量 | 停用保留历史关联 |
| 合作机构 | 保存机构、联系人、合作状态、班课／VIP 返点比例与说明、银行信息、跟进记录 | 返点是信息记录，未提供自动返点结算 |
| 报表统计 | 按时间等条件查看新增、跟进、到访、签约转化与渠道等分布 | 统计口径以页面和筛选条件为准 |
| 业绩排行 | 按销售比较客户、跟进、签约、订单与应收、实收等数据 | 金额涉及币种时需分别理解，不作为自动汇兑结算 |

跟进记录可填写方式、沟通内容、意向、到访和下次联系时间；只能删除本人 24 小时内的跟进记录。客户「已签约」由报名转学员自动写入，不能手工设为已签约或从已签约改回。跨校区创建、转移客户要求相应全校区范围。查重不会向无权查看的人员返回完整客户隐私。

## 3. 学员管理与订单

**解决什么问题：** 将招生档案、升学进展、购买项目与收退款记录关联，便于销售和担当教师各司其职。

### 报名与档案

「新学员报名」按「学员档案 → 项目缴费」办理，可从客户详情进入并预填信息。报名生成学号和学生端随机初始密码，初始密码只展示一次；后续可由有权限人员重置。

档案包括联系方式、紧急联系人、来日与签证信息、最终学历、语言学校、志望院校与专业、学科分类、销售顾问、担当老师和签约老师。各字段可在「成绩与档案设置 → 档案字段」中设为显示或隐藏、必填，或改名（例如把「最终学历」改为「年级」）。姓名、校区始终必填；默认模板下最终学历、语言学校也为必填。担当、签约老师必须选择教师身份工号。

「我的在籍学员」按权限提供「我销售的」「我担当的」视图；教师还可进入「我担当的学生」。担当视图隐藏订单和缴费操作并提供面谈入口。列表支持服务端分页与条件保留，在籍学员优先显示；可维护在籍、休学、结业、退学状态。有权限者可在「全部在籍学员」删除、恢复学员。

### 考试 / 证书与合格

| 内容 | 能做什么 | 关键规则 |
|---|---|---|
| 考试 / 证书 | 按「考试类型」配置录入等级、总分、分科成绩、考试场次（如 JLPT、EJU、雅思、托福、中考、高考） | 每种考试可设可选等级、总分满分、分科及各科满分、总分算法（相加 / 平均 / 手填）、最多回数、固定考试月份；标记为「高亮」的科目会在档案顶部显示历次最高分 |
| 合格信息 | 搜索或填写院校，记录学部／研究科、学科、专攻及合格日期 | 每位学员最多 5 条；院校建议支持部分简体与日文字形匹配 |

### 成绩管理（校内考试）

「学员管理 → 成绩管理」用于记录校内测验、月考、模拟考、期中期末等考试。

| 环节 | 能做什么 | 关键规则 |
|---|---|---|
| 新建考试 | 选择科目模板（可临时增减科目），填写名称、类别、日期、校区；关联班课时自动带入班级学员，也可追加个别学员 | 每个科目有代码、名称、满分和可选及格线（默认满分的 60%）；总分可按各科相加、各科平均（按精度取整，如雅思 0.5）或手动填写 |
| 录入成绩 | 表格逐格录入，或从 Excel 复制「学号 + 各科分数」整块粘贴；标记缺考、填写评语；低于及格线的分数标红 | 分数必须在 0～满分之间；修改科目后，系统按新科目重新计算总分 |
| 统计分析 | 参考人数、已录人数、缺考人数、平均分、最高分、最低分，各科均分与及格率，总分分布（得分率五档），排名 | 同分同名次；缺考不参与排名与均分 |
| 导出与发布 | 导出 Excel（成绩单 + 统计）；发布后学生在学生端「我的成绩」查看本人成绩、名次和平均分，并收到站内提醒 | 未发布的考试学生看不到；可随时撤回 |
| 学员成绩档案 | 学员详情「校内考试」页签显示历次成绩、名次、各科平均分、教师评语与得分率趋势图 | 有成绩权限者按自己的数据范围查看；能查看该学员的担当、销售人员也可查看 |

权限分四项：「查看」只读；「录入」只能给已有的考试录入成绩；「发布」可以发布或撤回到学生端；「管理」可以创建、编辑、删除考试和调整名单，并包含录入与发布。默认教务拥有管理权限，教师只有录入权限，事务只能查看。数据范围为「本人」时，只能看到自己创建的考试和自己任课班级的考试。

### 产品、订单、缴费与退费

「单期课程」与「套餐课程」维护价格、内容、启停和套餐包含的单期课程；「教授课程」则是教师的科目标签，两者用途不同。

项目缴费必须选择有效的私塾套餐，班级分配方式可选班课、VIP、班课+VIP；含 VIP 时必须填写正数课时与课程内容，并生成关联订单的 VIP 课时包。班课名单在「班课管理」或「出勤管理」维护，选购班课项目不等同于已经加入具体班级。

| 页面／操作 | 主要功能与规则 |
|---|---|
| 订单记录 | 查看明细、优惠、签约日期、应收、已收、已退与状态；支持后续选课缴费 |
| 登记缴费 | 记录类别、方式、日期、金额、经手人、凭证；支持分次登记，订单金额与状态随记录汇总更新 |
| 缴费明细 | 按条件查询并导出 Excel；金额按币种汇总 |
| 退费记录 | 保存金额、方式、日期、原因与操作人；累计退费不得超过已收金额 |
| 优惠 | 有优惠金额时必须选择优惠原因，优惠不能使应收金额为负 |
| 作废订单 | 必须没有缴费记录；关联 VIP 已有已用／待确认课时的，需先处理排课 |
| 删除误登缴费 | 需全部订单权限，且只能删除当天登记的记录；删除后已收不能低于已退 |

金额使用日元（JPY）或人民币元（CNY），按整数主单位记录。缴费、退费是人工登记业务，不提供在线扣款、银行转账执行或自动退款；退费也不应理解为自动撤销班级或课次。

## 4. 教务排课

**解决什么问题：** 统一教室资源与教师安排，减少重复录入、时间冲突及 VIP 课时核对成本。

### 视图与资源

| 页面 | 能做什么 | 关键规则 |
|---|---|---|
| 教室预约 | 按教室查看日／周占用、楼栋和课程类型；点击空白位置创建，点击课次查看详情 | 班课、VIP、其他占用共享资源表 |
| 课程表 | 按日期、教师等条件查看课程，进入课次确认、调课与课堂记录 | 修改操作需相应课次权限 |
| 月课表 | 月历及教室维度查看，按校区、教室、老师筛选，点击日期或课次操作 | 移动端采用适合窄屏的列表呈现 |
| 班课管理 | 建班、维护科目、默认教师／教室、学生名单、结课与重新开课 | 已结课班级不能继续新排课；有未来未取消课次时不能删除班级 |
| 教室管理 | 维护校区、楼栋、容量、类型、VIP 可用状态、启停 | 同校区教室名唯一；停用保留历史课次，不能用于新排课 |
| 我的课表 | 教师查看本人待上、待确认及历史课次，进入记录与确认 | 教师只能编辑自己的课次 |

### 冲突与批量排课

单次和批量排课均检查时间重叠的教室占用、同一教师安排，以及同一 VIP 学生在不同课时包中的安排。相邻课次结束时间等于下一节开始时间不视为重叠。这里的学生冲突检测针对 VIP 学生，不等同于全体班课学生的个人课表检查。

批量排课输入日期区间、星期（可全选为每天）、起止时刻、教室与教师，预览后生成；一次最多 200 节，单节时间不超过 12 小时。可跳过冲突日期；不跳过时，有冲突通常会阻止生成。拥有全部课次编辑权限者可显式忽略冲突生成，因此冲突检测不代表绝对禁止重叠。

同批次支持「仅本次」「本次及以后」「本批全部」修改或取消。批量操作只处理该批次待确认课次；「本次及以后」以所选课次时间为起点。批量调课可改时刻，修改日期需选「仅本次」。

### VIP班级管理与课时账本

VIP 课时包可关联学员、订单和多位任课教师，维护总课时、内容、在读／结业状态；列表优先展示未结业项目。教师仅查看自己任教的包，管理者按相应权限维护。

`剩余课时 = 总课时 − 已确认课时 − 待确认课时`

| 动作 | 课时变化 | 关键规则 |
|---|---|---|
| 约课 | 剩余转入待确认 | 剩余不足不允许；无需等上一节确认后再约下一节 |
| 学生确认 | 待确认转入已确认 | 只能确认自己的 VIP 课次，课程开始后方可操作 |
| 后台确认 | 待确认转入已确认 | 教务或有权限的任课教师操作，记录确认来源 |
| 自动确认 | 待确认转入已确认 | 下课满 48 小时后由后台任务处理；启动时运行，此后每 10 分钟检查，并非精确到秒 |
| 取消待确认课 | 待确认退回剩余 | 保留取消记录 |
| 删除已确认 VIP 课 | 已确认退回剩余 | 需要「删除已确认的 VIP 课次」权限，保留操作日志，实际课次标记为取消 |
| 调整总课时 | 修改总额度 | 总课时不得低于已确认加待确认 |

已确认课次通常只可修改备注；已确认 VIP 课时数的调整另需专门权限。结业课时包不能继续约课；尚有未取消课次的课时包不能删除。

## 5. 教学服务

**解决什么问题：** 让课堂、升学指导、文书和线下事务有统一记录与交接状态。

### 出勤管理与课堂记录

「出勤管理」提供班课点名、班级名单、按学生／班级／课程／日期统计，以及 Excel 导出和打印／PDF。点名状态为出勤、缺席、请假、迟到、早退，可逐人备注。名单可选择学员或粘贴学号／姓名导入；重名需改用学号。

当前统计口径为：`出勤率 =（出勤 + 迟到 + 早退）÷ 所在班级已开始且未取消的课次 × 100%`。未记录课次仍进入分母，界面单独显示未记录数；零课次时不显示有效比例。普通教师管理本人课次点名。

班课和 VIP 课次都可填写授课内容、作业、课堂表现，并设置是否对学生可见；学生端当前在「我的课时」查看可见的 VIP 课堂记录。

### 面谈预约、面试预约与记录

后台「面谈预约」「面试预约」分开管理，按日期、星期及自定义时间段批量发布，可预览、代约、取消预约、写记录。发布时跳过过去及与该主持老师已有时间段重叠的候选项，每段只接待一位学生。

学生在「面谈预约」页面切换面谈／面试，选择本校区或通用的未来可预约时间段。提交时提示：

> 您确定要预约吗？面谈前8小时将无法取消预约。

学生需在开始前超过 8 小时取消；进入锁定时间后无法自行取消。后台人员仍可在授权范围人工处理，已有面谈记录的预约不能再取消。后台查询、发布、代约及记录操作另受校区与主持人相关访问规则限制。

「面谈&面试记录」可记录学生、教师、日期、时长、日语、英语、文综、数学、志望校和专业、进学指导建议及其他内容；可关联预约或直接建记录。学生端可查看向其返回的指导字段，不展示所有后台内部字段。

### 文书修改

学生提交标题、文书类型、TXT 文件与备注，后台分配批改人员并发送站内提醒；批改者下载原文，上传修改文件并填写返还意见。当前页面要求上传返还文件；接口本身允许仅提供意见。仅批改权限的教师查看分配给自己的文书，文书管理员可分配、返还、删除与恢复。

学生自首次提交起 24 小时内仅可重新上传修改一次；超过窗口、次数用尽或已返还后不可再改。修改不重新计算 24 小时锁和 7 天期限。系统记录首次提交后 7 天的返还期限，后台支持逾期识别；这是服务期限与提醒，不会自动完成批改或阻止逾期返还。删除申请进入回收站，可由管理员恢复。

### 资料打印

学生上传 PDF 或 JPG/JPEG，选择黑白／彩色单面、页数及份数，系统报价后提交。PDF 尝试识别页数，识别失败需人工填写；JPG 计 1 页，提交前应核对报价。

| 项目 | 规则 |
|---|---|
| 黑白单面 | 10 日元／张 |
| 彩色单面 | 50 日元／张 |
| 总费用 | 页数 × 份数 × 单价 |
| 当天领取 | 按学员校区时区，12:00 前提交，当日 17:00 后 |
| 次日领取 | 12:00 整及以后提交，次日 17:00 后；未实现工作日／节假日顺延 |
| 学生取消 | 仅待打印申请可自行取消 |

后台可筛选申请、查看费用和预计领取时间、标记已打印并通知学生。打印费用为记录与报价，不代表线上收款；预计领取时间需结合实际完成状态。

当前限制：后台「已领取」按钮及筛选使用 `PICKED`，接口接受 `PICKED_UP`，因此领取状态的页面操作尚未闭环；后台当前列表也没有文件下载入口。事务人员需要协调实际文件取得和领取登记，不能将这两步视为已完整可用。

### 通知公告与资料

「通知公告」支持标题、正文、置顶、发布时间、校区及可见对象；「资料管理」支持上传附件、说明、校区和可见对象。对象可选教职工、学生或全部。教师通过「学校通知」「资料下载」查阅，学生从首页等入口进入通知、资料列表。

通知正文按纯文本处理，支持安全显示网页链接，不提供任意 HTML 富文本执行。上传单文件上限 20MB，并有格式与内容校验。业务列表按对象和校区筛选；上传文件地址本身以登录校验保护，不等同于逐文件归属授权。

## 6. 人事管理

**解决什么问题：** 汇总教师与员工的工作申报，按责任范围审核工资和交通费。

| 页面 | 能做什么 | 关键规则 |
|---|---|---|
| 工资申报 | 按月查看；填日期、类别、工时、时薪、交通费、起止站、内容；从课次一键申报 | 工资金额按工时 × 时薪四舍五入；合计另加交通费；单条工时大于 0 且不超过 24 小时 |
| 薪资申请管理 | 按月份、员工、状态等筛选明细，多选通过／不通过，按人汇总，导出 xlsx | 不通过需原因；已通过申报本人不能编辑或删除；驳回后修改重新待审核 |
| 薪资审核范围 | 为每位审核人配置全部、本校区、自定义校区与指定员工，或恢复默认 | 自定义校区与员工取并集；配置范围不替代薪资审核权限 |

从课次一键申报需要默认时薪；同一次批量生成按同一天只计一次交通费，不会替用户保证不同批次之间的每日交通费去重。未删除且未驳回的关联课次申报会阻止重复申报。

未单独配置审核范围时，角色数据范围为全部的审核人查看全部，其他审核人默认本校区。查询筛选不能扩大实际审核范围。除超级管理员外不得审核本人申报；超级管理员始终不受审核范围限制。这里是申报与审核工具，不执行工资转账或税费计算。

## 7. 系统设置

**解决什么问题：** 维护组织、人员权限和机构品牌，并留存关键业务操作记录。

| 页面 | 能做什么 | 关键规则 |
|---|---|---|
| 工号账户管理 | 创建工号、区分教师／职工等身份、设所属校区和额外的「可管理校区」与多个职务、教授课程、时薪、交通费、银行资料；重置密码、锁定、删除、恢复 | 工号唯一；删除后保留角色和科目；禁止锁定／删除自己及破坏最后一个有效超级管理员 |
| 职务权限 | 设置角色、权限点及本人／本校区／全部数据范围；可把角色设为「只读」（内置「只读管理员」：能查看全部、不能修改，用于演示或审计） | 多角色权限合并，数据范围取较宽者；各模块还会执行本人、任教关系及校区限制，不能把范围理解为任意跨模块授权 |
| 校区管理 | 维护代码、名称、地址、时区、排序，删除与恢复 | 默认时区 Asia/Tokyo；代码唯一，至少保留一个校区；日期显示与业务时区有关 |
| 教授课程 | 维护科目名称、分类、排序、启停，为教师多选关联 | 仅为科目标签，不设置价格；停用保留已有教职工关联 |
| 站点设置 | 站点名称、副标题、Logo、主题色、浏览器标题、教职工／学生登录文案、宣传标题及最多 6 条要点、页脚；预览、保存、恢复默认 | 需要专门权限；Logo 仅 PNG/JPG/WebP；自定义文本按原文保存，不自动生成各语言版本 |
| 操作日志 | 按操作者、动作、对象、日期等查询，查看详情及 IP | 记录登录与关键业务操作；不是数据库完整版本历史或一键回滚工具 |
| 业务规则 | 配置公海自动回收开关与未跟进天数、学号前缀、订单号前缀、上传大小上限、打印费与工资的货币（日元 / 人民币 / 自定义文字）、演示站是否允许只读账号排课，以及系统下拉选项 | 编号前缀只影响后续生成；上传上限同时受服务端校验；自动回收按定时任务执行并通知原负责人 |
| 成绩与档案设置 | 行业模板一键导入；维护考试类型（档案成绩）、成绩模板（成绩管理）、档案字段（显示 / 必填 / 名称） | 已有学员成绩在用的考试类型不能删除，只能隐藏；导入模板时，原有下拉选项保留为隐藏，教授课程只新增不删除 |
| 邮件设置 | 配置 SMTP、发件人、系统访问地址、测试邮件及“站内提醒同时发邮件” | SMTP 密码加密保存且接口不返回明文；找回密码与通知链接依赖准确的系统访问地址 |

新设密码需 8～64 位且同时包含字母与数字；学生初始／重置密码为 10 位随机值并只展示一次。改密、锁定或删除账号会使旧登录失效。

客户公海自动回收启用后，系统定时检查超过设定天数未跟进且仍由销售持有的客户，将其退回公海、记录操作日志并提醒原负责人。学号与订单号前缀、上传大小上限可由管理员调整；修改前缀不会批量重写已有编号。

SMTP 启用且档案中有邮箱时，可把站内提醒异步发送为邮件。教职工和学生可在登录页申请找回密码；重置令牌 30 分钟有效、仅能使用一次，申请结果不透露账号或邮箱是否存在。

### 首次安装与数据库

首次启动若没有 `DATABASE_URL`，系统进入安装模式。管理员在浏览器输入服务器控制台或 `server/.install-token` 中的安装码，选择 SQLite、MySQL / MariaDB 或 PostgreSQL，
填写站点、首个校区，选择行业模板并创建管理员后执行安装。系统自动建表、写入基础数据、生成 `JWT_SECRET`，并在同一进程切换到正式应用。

SQLite 为默认零配置方案；MySQL / MariaDB 与 PostgreSQL 使用对应 Prisma 驱动适配器。MySQL 驱动在选择该数据库时按需安装。
手动部署可配置 `.env` 后运行 `npm run db:setup -w server`。从 SQLite 切换到其他数据库时，命令只创建新库结构，已有数据需要部署者自行迁移和核验。

## 8. 学生端

**解决什么问题：** 让学生自行处理常见申请并核对进度，减少重复询问。

学生从 `/portal` 以学号和密码登录。首页聚合通知、预约、文书、打印和未读提醒；「我的课表」以周 / 月日历显示本人所在班课的课次和本人的一对一（VIP）课次（已取消的课以删除线标出），点开可看教室、老师、本人出勤和老师设为可见的课堂记录，上完的一对一课可直接确认课时；「我的成绩」显示已发布的校内考试成绩、名次与趋势；「我的课时」显示本人 VIP 账本、课次、确认状态及可见课堂记录；「面谈预约」支持面谈与面试；「文书修改」「资料打印」显示申请状态及后续操作。通知公告与资料下载通过页面入口进入，不一定出现在主导航中。

学生仅管理自己的申请和课时；账号需已开通且未删除。学生端没有自行新建 VIP 课次的约课入口，排课由教务或任课教师办理；学生负责核对、确认课时。

## 9. 多语言与手机端

**解决什么问题：** 支持不同语言背景的师生使用浏览器完成日常业务。

可选择简体中文、英语、日语、法语、西班牙语、俄语、巴西葡萄牙语、德语，选择保存在浏览器；界面词条与字典具备多语言机制，部分模块仍可能保留中文。人员姓名、通知正文、课程名称与管理员自定义品牌文案不自动翻译。

后台小屏使用抽屉菜单，多处列表切换卡片或隐藏次要列，对话框和工具栏随宽度调整；学生端针对手机组织申请表单与卡片。适用于手机浏览器，不提供原生 App、离线模式或所有复杂课表与桌面完全一致的展示。
